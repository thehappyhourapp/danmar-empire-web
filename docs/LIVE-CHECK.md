# Live check: the PropTx feed in the browser

Done by Daniel, in his own browser, after `PROPTX_TOKEN` (and `PROPTX_OFFICE_KEY` if known) are pasted into `.env.local` and set in Vercel. Nothing in the feed is read by anyone else before this. Each step says what to look at and what to do if it is wrong.

1. **The count.** Open `/collection`. The number of rows should equal the brokerage's active listings in the board system. Fewer rows than expected: the active filter is `StandardStatus eq 'Active'`; AMPRE's own examples filter on `ContractStatus eq 'Available'`, so if listings are missing, tell Claude Code and the filter changes to the field the feed actually populates. More rows than expected (other offices' listings): set `PROPTX_OFFICE_KEY` to the brokerage's ListOfficeKey and reload; without it the query matches `ListOfficeName` containing "DANMAR".
2. **The addresses.** Each row's title is the street address and its line reads "MLS® number · Listed by Danmar Empire Real Estate Corp., Brokerage". Open two detail pages: the H1 is the address, the remarks are verbatim, the specification strip shows only fields the record carries. Any address that reads oddly (unit numbers, suffixes) is a mapping question for `streetAddress()` in `src/lib/proptx.ts`; report the slug, not the record.
3. **The photographs.** Every row has a photograph and each detail page a hero plus the rest below. A grey block instead: open the browser's network panel, find the `/api/photo?u=` request that failed and read the hostname inside `u=`. If it is not on `ampre.ca` or `proptx.ca`, that hostname is added to the allow-list in `src/app/api/photo/route.ts` and `next.config.ts`. If the URL carries a signature or expiry parameter, say so: the proxy then re-fetches through the Media resource instead of the URL.
4. **A withheld address.** If any listing has InternetAddressDisplayYN off, its row and page should show the city and region only, "Address available on enquiry", and a slug of the form `/collection/listing-<mls>`. If such a listing shows a street, stop and report it; that is a licence breach to fix before anything else. If no listing is withheld today, note that the case is covered by the unit tests and move on.
5. **The revalidate route.** With `REVALIDATE_SECRET` set, open `/api/revalidate?secret=<the secret>`: it answers `{"revalidated":true,...}`. Then change a listing in the board system (or wait for one to change), open the route again, and confirm the Collection reflects it on the next load. Without the secret the route answers 403, and with no secret configured, 503.

Also confirm with PropTx, as `docs/CONFIRM.md` records: that on-demand reads of the brokerage's own listings at most once an hour sit within the agreement's "once every 24 hours" replication clause, and the exact attribution wording the DLA requires in the footer.
